# Ответы на контрольные вопросы

1. **HTML-скрапинг и REST API.** HTML-скрапинг извлекает данные из разметки,
   которая может меняться визуально и структурно. REST API обычно возвращает
   формализованный JSON/XML-контракт с документированными параметрами.
2. **`requests` и BeautifulSoup.** `requests` выполняет HTTP-запрос и
   получает ответ. BeautifulSoup разбирает уже полученный HTML и позволяет
   искать элементы CSS-селекторами.
3. **Пагинация.** Нужно находить ссылку следующей страницы, преобразовывать
   её в абсолютный URL, хранить `visited_urls` и прекращать обход при
   повторном URL. Для записей дополнительно хранится множество `org_id`.
4. **Scrapy Spider.** Spider работает внутри планировщика Scrapy: он создаёт
   запросы, передаёт ответы в callbacks, поддерживает middleware, задержки,
   robots.txt и экспорт. Обычный скрипт сам управляет циклом, сессией и
   обработкой ошибок.
5. **`ROBOTSTXT_OBEY`, `DOWNLOAD_DELAY`, AutoThrottle.** Первый параметр
   запрещает обход несогласованных путей, второй ограничивает частоту
   запросов, AutoThrottle адаптирует задержку под нагрузку и ответы сервера.
6. **Потоки и процессы.** HTTP I/O большую часть времени ждёт сеть, поэтому
   потоки перекрывают ожидание. CPU-bound код ограничен вычислениями Python,
   поэтому отдельные процессы позволяют использовать несколько ядер.
7. **`if __name__ == "__main__":` в Windows.** Windows запускает процессы
   методом `spawn`: дочерний процесс импортирует модуль заново. Условие не
   даёт повторно запустить главный код и создать бесконечный каскад процессов.
8. **Почему процессы могут быть медленнее.** Накладные расходы включают
   запуск процессов, сериализацию аргументов, передачу результатов и
   синхронизацию. Для маленьких задач они могут превысить выигрыш.
9. **Проверка ускорения.** Нужно сравнить не только время, но и количество
   успешных URL, ошибки, множество URL и хеши содержимого. В работе все режимы
   получили одинаковые 20/20 страниц и одинаковые сигнатуры.
10. **LEFT JOIN.** Он сохраняет все финансовые строки исходной витрины,
    даже если HTML-профиль отсутствует. INNER JOIN удалил бы организации без
    совпавшего веб-профиля и исказил бы финансовые итоги.
