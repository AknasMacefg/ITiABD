# Отчёт по лабораторной работе №3

## Цель и схема конвейера

Цель работы — получить структурированные сведения из многостраничного
HTML-каталога, сравнить BeautifulSoup и Scrapy, проверить качество данных,
измерить сетевой и вычислительный параллелизм и объединить результат с
витриной лабораторной II.

Конвейер:

1. `organizations.csv` преобразуется в локальный учебный HTML-каталог.
2. BeautifulSoup и Scrapy обходят три страницы пагинации и профили.
3. Сырые результаты сохраняются независимо в CSV и JSONL.
4. Выполняются проверки ключей, типов, дат и совпадения двух скраперов.
5. Очищенные записи объединяются с `data_mart.csv` через LEFT JOIN.
6. Локальный сервер с фиксированной задержкой используется для безопасного
   эксперимента I/O; тексты профилей — для CPU-эксперимента.

## Результаты скрапинга и качества

Оба скрапера получили 10 записей и 10 уникальных `org_id`. Наборы ключей и
общие поля полностью совпали. В текущем HTML фактических 404, дублей,
пропущенных полей и невалидных значений не возникло. В коде предусмотрены
отдельные ветви для HTTP-ошибок, сетевых ошибок, дублей, пропусков и
аномальных чисел/дат; тестовая 404-проверка подтвердила запись ошибки без
необработанного исключения.

Все 9 проверок из `quality_report.csv` имеют статус `passed`:

- 10 строк и уникальность ключа;
- отсутствие пустых обязательных полей;
- неотрицательные `reports_count`;
- корректные ISO-даты;
- целочисленные `org_id`;
- ISO 8601 `scraped_at`;
- совпадение ключей и полей BeautifulSoup/Scrapy.

## Сетевой benchmark

Использовались 20 URL локальных профилей, три запуска каждого режима:

| Режим | Медиана, с | Успешно | Ускорение |
|---|---:|---:|---:|
| Последовательно | 2.715872 | 20/20 | 1.000x |
| `ThreadPoolExecutor(2)` | 1.328425 | 20/20 | 2.044x |
| `ThreadPoolExecutor(4)` | 0.681042 | 20/20 | 3.988x |

URL и SHA-256 содержимого совпали во всех режимах. Потоки эффективны, потому
что во время ожидания сетевого ответа другой поток может выполнять запрос.
Общий `requests.Session` между потоками не использовался.

## CPU benchmark

Создано 200 больших фрагментов повторением локальных описаний. `analyze_text`
нормализует текст, выделяет слова и считает частоты слов и биграмм; HTTP-запросов
в вычислительной функции нет.

| Режим | Медиана, с | Ускорение | Результаты |
|---|---:|---:|---|
| Последовательно | 0.120563 | 1.000x | совпали |
| `multiprocessing.Pool(2)` | 0.280630 | 0.430x | совпали |
| `ProcessPoolExecutor(2)` | 0.328462 | 0.367x | совпали |

На данном размере задач процессы медленнее. Причины: запуск рабочих
процессов, сериализация текстов и результатов, ограниченное число ядер и
недостаточно крупная вычислительная нагрузка.

## Интеграция с витриной лабораторной II

`data_mart.csv` объединён с `catalog_clean.csv` по `org_id` через
`pandas.merge(..., how="left", indicator=True, validate="one_to_one")`.
Получено 10 совпадений, 0 строк только слева и 0 строк только справа.
Финансовые показатели сохранены в `data_mart_web.csv`.

График публикаций по секторам построен в
[`reports_by_sector.png`](reports_by_sector.png). При отсутствии профиля его
строка сохраняется, а новые веб-поля остаются `NULL`; только при группировке
для графика пропуск `reports_count` заменяется на 0. Интерпретация относится
исключительно к учебному набору.

## Пять основных выводов

1. **BeautifulSoup достаточен для небольшого контролируемого каталога**:
   последовательный `requests.Session` проще отлаживать и прозрачно
   управлять логированием.
2. **Scrapy полезен для масштабного обхода**: он предоставляет планировщик,
   `response.follow`, обработку robots.txt, задержки, middleware и экспорт.
3. **Потоки подходят для сетевого I/O**: на локальной задержке 0.12 с четыре
   потока дали почти 4-кратное ускорение без изменения результатов.
4. **Процессы не гарантируют ускорение**: для 200 текстов накладные расходы
   превысили выигрыш от параллельного CPU-исполнения.
5. **Надёжность обеспечивается проверками и журналом**: уникальный ключ,
   типы, даты, дубликаты и 404 проверяются явно, а неполные записи и ошибки
   не исчезают молча.
6. **Воспроизводимость требует локального стенда**: генератор каталога,
   фиксированная задержка, версии зависимостей, команды запуска и сохранённые
   CSV/JSONL делают измерения повторяемыми.

## Сравнение инструментов

| Критерий | BeautifulSoup | Scrapy |
|---|---|---|
| Простота для одной задачи | Высокая | Средняя |
| Управление обходом | Вручную | Планировщик Scrapy |
| Параллельность и задержки | Реализуются вручную | Middleware и настройки |
| Обработка robots.txt | Нужно реализовать отдельно | `ROBOTSTXT_OBEY=True` |
| Подходящий масштаб | Малый/средний | Средний/большой |
